测试方案要和理念相合，核心是把“疏而不堵”从一句口号拆成**可执行的断言**。每条理念对应一个测试层，不是传统的“输入A输出B”，而是“在什么条件下，系统必须表现出什么行为”。下面分五层，每层先说明测的是哪条理念，再说判定标准。

---

### 第一层：物理不变量（属性测试）

这一层不测业务逻辑，测的是模型自身的物理法则是否在任何输入下都成立。用属性测试生成随机输入，断言不变量。

**球大小**：任何强化后 `size ∈ [0, size_max]`，永不为负、永不超上限；饱和后增量趋近零但最近注水时间仍刷新。
**管道粗细**：`w ∈ (0, 1]`，永不归零；合并时取最大值不叠加，不会因合并突然变粗。
**水量**：每跳损失后水量非负；**分配守恒**——球的当前可分配水量按 `1 + w_eff` 分到各条出边后，各份之和等于可分配总量（浮点误差 `< 1e-9`），且**每条出边分到的水量 ≥ 0**；损失率是 `w_eff` 的单调递减函数——管道越细，损失越大；损失永不超过 `loss_max`。
**稳定性 S**：`S ∈ (0, S_max]`，强化后只增不减、永不倒退；`delta ≤ 0`（路过球、维度不匹配）时 `S` 完全不变——“没想起来”不留痕迹。
**阻塞计数**：`blocked_effective ∈ [0, blocked_pass_count_stored]`，衰减只减不增、永不为负；无阻挡时间戳时等于存储值。
**管道阻力**：`w → 0` 时阻力趋近上限但永不无穷大，意味着**任何管道在足够大的水量下都能被突破**。这条是“不封死”理念的物理断言。

判定：随机生成一万组输入，不变量零违反。违反任何一条，说明物理法则有漏洞。

### 第二层：理念断言（每条约一条测试）

这一层把每条设计理念转成一个具体场景的断言。

**“不删除，只降可提取性”**：构造一个球，让它在无强线索的情况下衰减到极小，确认它仍在存储中、状态仍是 `active` 或 `archived` 而非 `deleted`；然后用一条与它高度相关的强线索注水，断言它被点亮。**如果衰减到极小后就永远点不亮，这条理念就被证伪了。**

**“阻力不是开关”**：构造一条极细的管道（`w` 接近 0），用常规水量注水，断言水流不通过但损失照常发生；再用强线索放大水量，断言水流通过。同一条管道，两种水量，两种结果——证明它是阻力不是开关。（分配环节的专门断言见本节「多出边水量分配」原则三。）

**“补充 > 损失当且仅当球大、与水源同向、强相关”**：三组对照——大球同向强相关（补充 > 损失）、小球弱相关（补充 < 损失）、大球与水源反向（`cos(S,B)≈0`，补充 = 0）。断言水流在第一种情况下能继续扩散，后两种情况下衰减停止。**注意“停止”的粒度**：停止的是**这条出边**，不是整个球——一条出边因补充 < 损失而停止，不影响该球其他出边按各自分到的水量继续推进。预期值按“每条出边独立判断”写，不要写成球级别的终止开关。注：设计早期写作“新鲜”，现已废弃（新鲜度与 `size` 的 `exp(-Δt/S)` 重复计权），改用 `relatedness = cos(query, B)`（原始查询嵌入与球嵌入的余弦）。

**“相关性只由记忆内容决定，与水量无关”**：相关性 = `cos(语境, B) × 路径长度折扣`，语境在结算时是流动加权语境（`(1-α)×原始查询 + α×路径球加权平均`，α=0.2、权重为各球 water 占比）、流动逐跳时是原始查询嵌入。它只回答“这条记忆与当前输入有多相关”，**不回答“这次被激活得多强”**。一句话：**水负责“点亮”，不负责“记账”，也不负责“说话”**（docs/03 §6.1 边界约束）——水只参与分配、阻力判断、是否点亮，不进入相关性、不决定强化量、不参与注入排序、不乘进任何阈值。测试：固定同一个目标球 `B` 和同一 query，两次结算唯一区别是 `LitBall.water`（如 `0.01` vs `100.0`），断言两次的强化增量**完全相同**；再构造 `B` 与 query 正交（`cos(query,B) = 0`），用强线索量级的水（`water = 3.0`）注水，断言 `B` 仍**不**被判为强化球。**为什么必须守住**：水量量纲随 `base_water_amount` / `split_mode` / 损失参数漂移；一旦乘进相关性，`strengthen_threshold_X`（默认 0.7）就失去语义——强线索 `W₀×3` 时，语义仅 0.25 相关的球 relevance 也能到 0.75 而被判为“强化球”，阈值退化成不可校准的魔数。（实现位置：`crates/dayu-flow/src/settle.rs` 的 `calculate_path_relevance`；测试：`relevance_is_independent_of_water_amount`、`large_water_does_not_promote_off_origin_ball`。）

**“同等相关性下不区分激活强弱”**：两个球语义相关性相同（如同一水源、同一深度、内容与 query 余弦一致），唯一区别是 `LitBall.water`（如 1.0 vs 0.02），断言它们在注入序列中的**相对顺序不受水量影响**（同分时按 id 稳定排序）。水量差异反映的是路径通畅度，不是回答价值。若未来要区分，应新增**显式的 `activation_strength` 第三因子**（默认关闭、有对照实验支撑），不得通过往相关性里乘 water 实现——隐式乘数无法单独关闭、无法单独观测、无法单独对照。

**“资格看语义、幅度看路径”**：`semantic_sim` 决定“够不够相关、值得被强化”，`semantic_sim × 跳数折扣` 决定“强化多少、排序多靠前”。测试：构造 `depth = max_flow_depth`（5）、语义几乎完全匹配（`sim ≈ 0.997`）的球，断言它**仍被强化**，且增量 = `base_reinforcement × sim × min_discount`；同时断言达标球的最小增量（`base × 阈值 × min_discount`）**大于**最低强化值（`base × min_strengthen_value`），否则“语义不达标只是路过”的球会比“语义达标但路径最远”的球强化得更多。**为什么必须守住**：若资格也用 `sim × 折扣`，而 `strengthen_threshold_X(0.6) > min_discount(0.5)`，则深度 4/5 的球在数学上永远过不了资格线——远处联想被点亮却永不被强化，等于“只贡献路径、不获得强化”，违背“路径级强化”理念。（实现：`crates/dayu-flow/src/settle.rs` 的 `PathRelevance`、`reinforce_balls`；测试：`deep_ball_with_high_semantic_sim_is_still_strengthened`、`minimum_reinforcement_is_below_any_strengthened_ball`。）

**“流动只点亮、结算才强化”**：流动过程中快照球大小和管道粗细，断言流动结束后、结算前，它们**没有任何变化**；结算后断言变化发生。这条测的是职责分离，不是数值。

**“路径级强化”**：构造两条路径——一条经过三个球、一条只经过一个球，让两条路径都被结算。断言三个球路径上的球和管道**都**获得了强化，而不只是终点球。再断言同一球出现在两条路径上时，取最大路径相关性强化一次，不累加。

**“不切割完整球”**：构造一个内容很长的球（远超 token 预算）和一个内容很短的球，注入预算只够装一个。断言长球**整个不被注入**，短球完整注入；不存在“注入了长球的前半段”的情况。

**“纠正可逆、审计先行”**：删除一个球的内容，断言 `correction_log` 先于状态变更写入；然后执行反向操作，断言球恢复到纠正前状态，强度守恒（不重复计数、不为负）。断言硬删必须显式确认，默认软删。

**“短期不删、被问到就醒”**：构造一个被归档的球，用余弦 ≥ `start_ball_threshold` 的常规线索注水，断言它**能**被检索到、被点亮，且命中后 `status` 已翻回 `active`（无临时态、无 TTL）；再用低于阈值的线索，断言它不被点亮、状态保持 `archived`。

#### 多出边水量分配（`1 + w` 加权）

分配规则：`water_i = water_available × (1 + w_eff_i) / Σ_j(1 + w_eff_j)`，先分配、再逐条判断，失败的损失不回收。以下六条中，原则一/二/四/五归回归测试层，原则三为理念测试，原则六归第四层对照实验。

**原则一：分配守恒。** 给定一个球的可分配水量和它的所有出边，断言各出边分到的水量**之和等于可分配总量**（不多不少），且每份 ≥ 0。分配阶段不产生、不消灭水；损失只发生在每条管道**各自判断之后**。防止“某条管道多分了一点”或“分配后总量对不上”。

**原则二：加权比例正确。** 三条出边 `w` = 0.9 / 0.5 / 0.1，断言分配比例等于 `1.9 : 1.5 : 1.1`，**不是** `0.9 : 0.5 : 0.1`，也不是 `1:1:1`。直接测 `1 + w` 公式，防止实现退化成按 `w` 直接分或平均分。

**原则三：细管保底非零（理念测试）。** 构造 `w` 极接近 0 的管道，断言它分到的水量**严格大于零**（即使极小）；再用足够大的总水量注水，断言这条管道最终能通过阻力。测的是“分配规则不封死细管”——若细管分到零水就永远过不去，与“阻力不是开关”直接冲突。**这条比数值错误更严重，失败即理念被证伪。**

**原则四：先分配后判断，损失不回收。** 构造三条出边，两条过不去、一条能过。断言：过不去的两条各自扣了损失、水**没有回收**给能过的那条；能过的那条拿到的水量是**分配时**分到的那份，不是“另两条失败后重新分配”的水量。测的是顺序——分配是一次性的，判断是独立的。

**原则四之二：回边不参与分配。** 中间球有两条出边——一条回边（指向已访问的来路）、一条前进边。断言前进边拿到**全额**水量（回边没有分走一半）。若这条失败，链式扩散会每跳腰斩，`max_flow_depth` 形同虚设。

**原则五：全失败时水耗尽、球被润湿。** 所有出边都过不去，断言该球的可分配水量**全部损失**、无下游被点亮、该球被记一次“润湿”（供后续 `blocked_count` 与舌尖效应使用）。测“想不起来就是白费力气”的边界。

**原则六：分配模式对照（第四层）。** 同一张图、同一批起始球，分别用 `weighted` 与 `equal` 跑，断言两者结果**可能不同**。完全相同说明分配规则在当前参数下不产生实质影响，需检查是否被其他机制掩盖；不同则记录差异方向是否符合预期（粗管路径应更容易走通）。允许“无差异”作为有效结果，但必须**显式记录**。

**“稳定性随强化增长，且只对强化球增长”**：`S += (S_max − S) × delta / (delta + k)`。测试三条——①同一球连续强化 N 次，断言 `S` 单调不减且不超过 `S_max`（proptest：`stability_growth_is_monotone_and_capped`）；②印象球/路过球（最低强化值）被点亮后断言 `S` 增长可忽略（`minimum_tier_barely_grows_stability`）；③`delta = 0` 时断言 `S` 完全不变（proptest：`zero_delta_never_grows_stability`）。**为什么必须守住**：若路过球也涨 S，则“每次检索都会让所有被点亮的路更牢固”，`archive` 永远触发不了，主图无限膨胀。**间隔效应不需要单独实现**——饱和增长 + delta 驱动已经隐含它：连续强化的 delta 递减、间隔强化的 delta 较大，最终 S 更高。（实现：`crates/dayu-flow/src/settle.rs` 的 `grow_stability`。）

**“阻塞记忆降阻、遗忘后恢复”**：管道被水挡住时 `blocked_pass_count += 1`、`last_blocked_at = now`，下次有效阻力按 `1 − blocked_count × block_soften_factor` 下降（上限 `block_soften_max`）。测试——①构造细管 + 常规水量，断言水流不通过且 `blocked_pass_count` 加一（`blocked_pipe_is_counted_and_softens_resistance`）；②同一管道第二次注水，断言阻力比第一次低、通过概率上升；③放置 `blocked_pass_count_stability` 天后再注水，断言计数按 `exp(-Δt/S)` 衰减（`blocked_count_decays_after_idle_period`）、阻力回到接近原始值。**为什么必须守住**：被挡是“这次水不够”，不是“这条关联没用”——若计数只增不减，一次偶然的弱线索会把这条管道永久改成低阻力，等于用噪声改写结构。

**“归档可检索、唤醒无临时态”**：归档不是删除，是“降低可提取性”。测试——①构造 `archived` 球，用余弦 ≥ `start_ball_threshold` 的线索注水，断言它**被检索到、被点亮**，且命中后 `status` 直接翻回 `active`（无 `pending`/TTL 中间态）（`recall_wakes_archived_start_ball`）；②低于阈值的线索断言它不被点亮、状态保持 `archived`；③`archive_sweep` 只归档“超过 `archive_inactive_days` 且 `size_effective < archive_size_threshold`”的球（`archive_sweep_archives_only_idle_and_decayed`）；④活跃球数超过 `max_active_balls` 时按最弱优先归档（`archive_sweep_enforces_active_cap_by_weakest_first`）；⑤断言归档球**仍参与检索索引**（`search_includes_archived_but_excludes_deleted`）——若归档区不建索引，“被问到就醒”永远做不到。

**“多源汇合：重叠共享预算、不重叠各自独立”**：一次输入可能同时来自用户消息、工具结果、模型输出。测试——①两个源分别命中互不相交的球集合，断言两组各自拿到完整 `total_water_budget`、互不抢水（`disjoint_sources_get_independent_water_budgets`）；②两个源命中同一个球，断言该球只拿一份水（合并而非叠加）、且合并值 = `min(和, 最大单源 × merge_ratio)`（`overlapping_sources_share_one_water_budget`）；③断言合并判定用**起始球重叠**而非嵌入相似度——两个源嵌入可以完全不同但指向同一批球。

**“强线索放大总量，但不改变分配比例”**：起始球与查询的余弦 ≥ `strong_cue_threshold`（默认 0.8）时，`total_water_budget × strong_cue_multiplier`（默认 3.0）。测试——①同一组起始球，一条带强线索一条不带，断言总水量差 3 倍（`strong_cue_multiplies_total_water`）；②断言分配比例（各球占比）**完全不变**（`strong_cue_preserves_split_ratio`）；③断言 `strong_cue_multiplier = 1.0` 时总水量守恒、与关闭强线索等价（`zero_source_bonus_keeps_total_water_conserved`）。**为什么比例必须不变**：强线索只回答“这次输入很明确”，不回答“哪条记忆更重要”——若连比例一起放大，等于给强线索额外加了一层偏置，两个机制的作用会纠缠在一起，无法单独观测。

判定：每条理念至少一个场景，场景的断言必须能区分“理念成立”和“理念被违反”。不能写成“看起来对”的模糊检查。

### 第三层：流动与结算的确定性（固定场景回归）

这一层用固定输入、固定配置、固定随机种子，断言输出完全可复现。目的是保证“同样的输入永远得到同样的结果”——这是可审计性的基础。

**起始球选择**：给定一组球和一条查询，断言选中的起始球集合、注水量分配比例与预期完全一致。
**流动路径**：给定子图和水量，断言点亮的球集合、每条路径的跳数、每跳剩余水量与预期一致。**多出边场景的预期值必须按 `1 + w_eff` 重新手工计算**——每个球进入逐跳前的起始水量不再是“可分配总量”，而是分配后属于该出边的那一份。
**结算增量**：给定点亮集合和相关性，断言每个球的强化增量、每条管道的粗细增量与预期一致。
**注入排序**：给定同一批球，断言排序结果稳定；切换配置中的排序指数，断言排序按预期变化。

判定：这些测试的预期值是手工计算的，不是从系统输出反填的。如果实现变了但预期没变，测试失败说明行为漂移。

### 第四层：对照实验（证伪概念赌注）

这一层不是“测对错”，是“测这个模型的世界观是否成立”。每个对照实验对应一个概念赌注。

**赌注一：动力学扩散是否优于查询检索。** 同一批对话、同一批记忆，分别跑水流扩散和向量 Top-K，记录两边的点亮集合、注入块、以及后续模型是否引用了注入的记忆。断言两者结果**不同**（证明修正确实改变了行为），并统计扩散是否召回了 Top-K 漏掉的相关记忆。如果扩散的召回质量显著低于 Top-K，这个赌注就被证伪了。

**赌注二：阻力上限是否导致假阳性唤醒。** 记录每次“强线索突破低阻力管道”的唤醒，事后标注被唤醒球与当前语境的真实相关性。断言“突破阻力”的唤醒中高相关占比不低于常规唤醒——如果显著更低，说明“永不封死”在制造噪声。

**赌注三：路径级强化是否导致联想僵化。** 连续 N 次激活中，统计被点亮路径的重复率、新路径发现率、老路径和新路径各自的注入命中率。断言重复率不持续上升，或新路径发现率维持在合理区间。如果系统越来越只走那几条老路而命中率不升，说明强化导致了僵化。

**赌注四：管道决定损耗是否真的改变了行为。** 用 `PipeWeightLossModel` 和 `ConstantLossModel` 跑同一批输入，断言两者的点亮集合和注入块**不同**。如果完全相同，说明“管道决定损耗”这个修正在当前参数下没有实际效果——它可能被其他机制掩盖了。

**赌注五：激活强度是否该参与注入排序（`activation_strength` 第三因子）。** 默认**关闭**——排序只看相关性（`a=1, b=0`）。开启后，排序分额外乘 `(water / W₀)^c`（归一化到无量纲，否则量纲随配置漂移，无法校准）。对照实验：同一批输入分别用 `c = 0 / 0.25 / 0.5 / 1.0` 跑，除注入命中率外，**必须同时观测“被注入球的 water 分布”与“注入内容的新旧分布”**。断言：若 `c > 0` 命中率提升，应伴随“强水量球”而非“老球”占比上升；若提升来自后者，说明这个因子在偷偷做巩固度偏置（与 `b > 0` 同一个陷阱），应关闭。**如果 `c = 0` 与 `c > 0` 的命中率无差异，说明激活强度不携带回答价值信息，这个因子应被删除而不是留着。**

判定：对照实验的断言不是“哪个更好”，是“两者是否不同”和“差异的方向是否符合预期”。没有差异，说明某个机制是装饰；差异方向相反，说明某个赌注错了。

### 第五层：工程约束（与理念无关但必须守住的底线）

这一层不测理念，测的是“理念在工程上是否真的落地了”。

**前缀缓存**：注入前后对比 system prompt 和工具 schema 的字节，断言完全不变；注入只追加在 messages 尾部。
**停机恢复**：模拟进程 kill -9，重开后断言已提交的结算、新球、纠正全部存在，未提交的回滚；`pending_retry` 表被重试。
**配置化**：审计代码中是否残留硬编码系数；修改配置文件中任一系数，断言行为按预期变化，不改代码。
**独立测试**：每个 crate 的默认测试零真实依赖、秒级完成；`dayu-flow` 的 dev-dependencies 里不出现 TriviumDB 或 ONNX。
**单一衰减点**：断言 `size_effective = size × exp(-(now - last_watered)/S)` 在代码中**只存在一处计算**——用 `grep` 审 `exp(` / `powf` / `freshness` 在消费方（起始选择、补充、排序）零命中。行为断言：固定一个球，将 `last_watered` 往前推 3 个 S，断言三处消费方的结果**同步按同一个倍率下降**（若某处降得更多，说明那里又乘了一次衰减）。对应设计 §4.6。
**衰减必须物化**：构造一个放了一年的球（`size = 8.0`，`size_effective ≈ 0`），执行一次强化，断言写入后 `size` **接近增量本身（约 1.0）而不是 9.0**——若存储值跳回历史峰值附近，说明跳过了物化。同时断言读取路径（起始选择/补充/排序/注入）**不产生任何写操作**（存储快照前后一致）。
**写入必须带 now**：`increment_ball_size(id, delta, now)` 的 `now` 由调用方（`SettleEngine::clock`）传入，不在存储层取 `Utc::now()`——否则注入 MockClock 的确定性测试会与真实时钟错位，物化结果不可复现。管道强化同理：`upsert_pipe` 前先用 `effective_thickness(now)` 折算并刷新 `last_flowed`。
**可观测性**：断言关键路径记录了指标；断言对照实验能通过旁路调用 `recall` 而不影响主路径注入。

判定：每一条都是可执行的检查项，不是“代码 review 时注意一下”。
