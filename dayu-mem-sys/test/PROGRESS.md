## 三、已完成：1000 球单组试跑

**场景**：8 个主题簇（Rust / 数据库 / 前端 / 运维 / 算法 / 产品 / 写作 / 生活），每簇 9 个关键词 × 5 个模板，簇内 2~3 条边（w 0.5~0.9），簇间每 50 球 1 条弱边（w 0.05~0.15）。

**参数**：`budget = 2.5`、`sig = 1.0`、`start_top_n = 1`、`start_ball_threshold = 0.3`

### 结果

```
球数 1000，管道 2268
建图 45,012 ms
连管道 118,991 ms
db 大小 5 MB
单次 recall 102 ms

平均点亮 1.4 个球
平均被挡 5.1 条管道
平均注入 1.1 块
```

### 问题

**水一跳都走不出去**。

原因不是 budget 太小，而是 `start_top_n = 1` 只选 1 个起始球：

```
水从 1.0 出发
→ 分叉到 2~3 条出边（各 ~40%）
→ 扣损 ~20%
→ 剩 ~0.32
→ 低于阻力下限 0.5
→ 全部被挡
```

### 更根本的问题：绝对阈值在大图上失效

`start_ball_threshold = 0.3` 是绝对阈值。球数上万时，**总有几十个球余弦超过 0.3**，起始球数量随图规模增长，最终淹没整图。

**已修复**（`30d8167`）：新增 `start_ball_relative_threshold = 0.85`，起始球必须同时满足：

```
cos ≥ start_ball_threshold (0.3)          ← 绝对：挡住完全不相关的球
cos ≥ 最佳命中 × 0.85                      ← 相对：挡住“勉强相关”的球
```

相对阈值让起始球数量只取决于「与最佳命中的接近程度」，与图规模无关。

**优化方向**：

| 方案 | 预期收益 |
|:--|:--|

**最有效的是第三条**：建一次 20000 球的图，然后只改 `total_water_budget` 重跑 recall。但当前 `init` 会重建实例，需要确认 TriviumDB 能否复用已有 db 文件。
